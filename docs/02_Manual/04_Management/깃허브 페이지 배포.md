Quartz는 기본적으로 정적 사이트 생성기이므로, HTML 파일만 올려둘 수 있는 곳이라면 어디든 배포가 가능합니다.
가장 대중적이고 무료인 **GitHub Pages** 배포 방법을 중점적으로 정리합니다.

> **💡 중요:** 배포 전에 `quartz.config.ts`의 `baseUrl` 설정이 올바른지 반드시 확인하세요! (RSS 및 사이트맵 생성에 필수)

---

## 1. 깃허브 액션 설정 (GitHub Actions)

Quartz 4.0부터는 깃허브 액션을 통해 **자동 배포**를 지원합니다.
`quartz/.github/workflows/deploy.yml` 파일이 존재해야 하며, 내용은 아래와 같습니다.

```yaml
# quartz/.github/workflows/deploy.yml 핵심 내용
name: Deploy Quartz site to GitHub Pages

on:
  push:
    branches:
      - v4 # v4 브랜치에 푸시될 때마다 실행

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: "pages"
  cancel-in-progress: false

jobs:
  build:
    # ... 빌드 설정 (Node.js 설치, 의존성 설치, npx quartz build 실행)
  deploy:
    # ... 배포 설정 (GitHub Pages로 업로드)
````

### 배포 활성화 방법

1. 깃허브 저장소의 **Settings** 탭으로 이동합니다.
    
2. 사이드바의 **Pages** 메뉴를 클릭합니다.
    
3. **Build and deployment > Source** 항목을 **GitHub Actions**로 변경합니다.
    
4. 이제 로컬에서 `npx quartz sync`를 하면 자동으로 배포가 시작됩니다.

## 2. 커스텀 도메인 연결 (Custom Domain)

`내아이디.github.io` 대신 `mysite.com` 같은 나만의 도메인을 연결하는 방법입니다.

1. 깃허브 저장소 **Settings > Pages** 메뉴로 이동합니다.
    
2. **Custom domain** 칸에 구매한 도메인을 입력하고 Save를 누릅니다.
    
3. **DNS 설정 (도메인 구입처에서 설정):**
    
    - **서브 도메인 (예: `blog.example.com`):** `CNAME` 레코드에 `내아이디.github.io`를 입력합니다.
        
    - **루트 도메인 (예: `example.com`):** `A` 레코드를 추가하여 깃허브 IP 주소 4개를 입력합니다.
        
        - `185.199.108.153`
            
        - `185.199.109.153`
            
        - `185.199.110.153`
            
        - `185.199.111.153`

## 3. 트러블슈팅 (Troubleshooting)

### Q. 배포가 안 돼요! (Environment Error)

"Environment protection rules" 관련 에러가 뜬다면:

1. 저장소 **Settings > Environments** 탭으로 이동합니다.
    
2. `github-pages` 환경을 휴지통 아이콘을 눌러 **삭제**합니다.
    
3. 다시 `npx quartz sync`를 하면 깃허브 액션이 올바른 환경을 재생성합니다.
    

### Q. 변경 사항이 반영이 안 돼요!

가장 흔한 원인은 **변경 사항을 푸시하지 않은 것**입니다.

반드시 `npx quartz sync` 명령어를 통해 커밋과 푸시를 완료했는지 확인하세요.
