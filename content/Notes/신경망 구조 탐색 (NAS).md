NAS(Neural Architecture Search)는 신경망의 구조(아키텍처)를 사람이 직접 설계하지 않고 **자동으로 탐색**하는 기법이다.

<u>**왜 자동화가 필요한가?**</u>
신경망 설계는 레이어 수, 활성화 함수, 연결 방식 등 수많은 선택지가 얽혀 있다. 경험 많은 연구자가 직접 설계해도 이게 최적인지를 보장할 수 없다. 특히 모바일·임베디드처럼 자원이 제한된 환경에서는 성능과 효율성을 동시에 잡아야 하는 조건이 붙어, 사람의 직관만으로는 한계가 있다.

NAS는 이 설계 과정 자체를 최적화 문제로 바꾼다.

## 3가지 구성요소

NAS는 항상 세 가지 질문으로 분해된다.

**1. 탐색 공간 (Search Space)**
"어떤 구조들 중에서 찾을 것인가?"
탐색 가능한 신경망 구조의 집합이다. 레이어 유형, 활성화 함수, 연결 방식, 깊이 등이 여기서 정의된다.

공간이 너무 넓으면 탐색 비용이 폭발하고, 너무 좁으면 좋은 구조를 놓친다.
이 트레이드오프를 줄이기 위해 **셀 기반 설계(Cell-based Design)** 가 자주 쓰인다 — 작은 모듈(셀)만 탐색하고, 이를 반복적으로 쌓아 전체 네트워크를 구성하는 방식이다.

**2. 탐색 전략 (Search Strategy)**
"어떻게 탐색 공간을 뒤질 것인가?"

| 전략         | 방식                          | 비고                       |
| ---------- | --------------------------- | ------------------------ |
| 강화 학습 (RL) | 에이전트가 구조를 생성, 성능 피드백으로 학습   | 성능 좋지만 비용 큼 (NASNet)     |
| 진화 알고리즘    | 교배·돌연변이로 세대별 진화             | 직관적, 역시 비용 큼 (AmoebaNet) |
| 그래디언트 기반   | 탐색 공간을 미분 가능하게 정의, 기울기로 최적화 | 빠름 (DARTS)               |

**3. 성능 추정 전략 (Performance Estimation Strategy)**
"선택한 구조가 얼마나 좋은지 어떻게 평가할 것인가?"
매번 완전히 훈련(Full Training)하면 정확하지만 시간이 너무 오래 걸린다. 가중치 공유(Weight Sharing)나 프록시 모델(Proxy Model)로 평가 비용을 줄이지만, 추정 정확도가 떨어지는 트레이드오프가 생긴다.

## 세 구성요소의 순환

탐색 전략이 공간에서 구조 후보를 선택 → 성능 추정 전략이 평가 → 결과를 다시 탐색 전략에 피드백 → 더 나은 구조 탐색. 이 루프로 순환된다.
